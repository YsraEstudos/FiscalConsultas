## 2024-04-29 - [Bounded LRU Cache for Stemmer]
**Learning:** Instantiating `PortugueseStemmer` inside the `NeshTextProcessor` facade and directly calling its `stem` method causes redundant CPU-intensive text normalizations for the same words, particularly across large datasets or repetitive FTS queries where the vocabulary is bounded. Applying `@functools.lru_cache` to a module-level proxy function significantly speeds up NLP stemming. Never apply `lru_cache` directly to an instance method.
**Action:** Always use a module-level bounded `lru_cache` on a decoupled proxy function when caching results from an instance method (e.g., stemming) across multiple instances to avoid including `self` in the cache key and causing cache misses or memory leaks.
## 2024-05-21 - [Optimize Python String Stripping]
**Learning:** For optimal performance and strict correctness when stripping non-numeric characters from strings in Python, using a generator comprehension like `"".join(c for c in s if c in "0123456789")` is significantly faster (~13% in this codebase) than regex `re.sub(r"[^0-9]", "", s)`. Furthermore, it is strictly safer than using `filter(str.isdigit, s)` because `str.isdigit()` allows Unicode digits (like superscripts), which alters the intended ASCII-only behavior of `[^0-9]` or `\D`. Chaining `.replace().replace().split()` is also ~4.4x faster than `re.split(r"[;,\s]+")`.
**Action:** Always prefer generator comprehensions with strict inclusion checks (e.g., `if c in "0123456789"`) over `re.sub` or `str.isdigit` for stripping non-numeric ASCII characters, and favor chained `.replace()` calls over `re.split()` for simple delimiter normalization.
